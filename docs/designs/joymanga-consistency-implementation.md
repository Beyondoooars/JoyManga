**本轮已按方案修改生产代码并通过既有流程重新生成绑定；未安装或升级依赖，未提交或发布，也未进行 Android 真机验证。第 9 节记录实际检查结果和未覆盖范围。**

实施前需要确认：

- 保留 `src/components.d.ts` 的既有修改和 `UPGRADE_PLAN.md`，不将它们纳入本方案。

- 保留 Android 下载、离线阅读、CBZ 管理、签到、收藏查看与同步；不恢复阅读器复杂 HUD，不添加装饰性控件或操作说明小字。

## 2. 顺序和依赖

```text
阶段一：状态与数据边界
B01 配置版本
B02 下载完成终态 ─→ B03 创建/恢复与归档登记互斥
             └─→ B05 队列启动容错
B06 合并包身份识别 ─→ B07 书库刷新调度

阶段二：界面反馈
B08 后台错误承接 ─→ 移除通用 ERROR 通知
B09 确认框返回语义

阶段三：减少重复工作与小幅契约清理
B02 + B03 + B08 ─→ B10 队列批量写入 ─→ B11 批量下载失败分类
B07 + B08 + B09 ─→ B12 生成绑定与错误文案清理

阶段四：测量后才决定是否继续
B06 + B07 + B10 ─→ 队列 v2 / 文件解析缓存 / 大图片策略评估
```

B01、B02、B04 可独立开始。B03 依赖 B02，因为终态、任务移除和归档调度应先有一致语义，再给入口加互斥；否则两个改动同时出现时难以判断回归来源。B05 接续 B02 的启动/备份/事务 `Done` 分类与补跑规则；B04 也可独立实施。

B08 未完成前，不删除 `initLogListener` 的后台错误通知。B10 不改变队列 JSON 格式，也不与 B02 合并成一个“大状态机重写”。同文件有多批改动时，按 B02→B03→B10、B07→B08→B12 的顺序落地，每批独立审查。

## 3. 阶段一：状态与数据边界

### B01 配置版本只从当前常量产生

**目标：** 修复默认配置和提交配置写回 v1，导致下一次启动再次执行 v1→v2 迁移的问题。

**文件：** 修改 `src-tauri/src/config.rs`、`src-tauri/src/config_updates.rs` 及其已有测试。

**实施：**

1. 让 `CONFIG_SCHEMA_VERSION` 对配置提交模块可见；`Config::default` 和 `commit_locked` 统一写入该常量。
2. 保留无版本域名迁移和 v1 私有书库重置，不借本次修改删除迁移。
3. 检查 `merge_config_changes` 对 `schemaVersion` 的忽略、启动保存和备份恢复，确保没有另一条路径把版本重新写低。
4. 不在本批顺带实现“未来配置版本不启动”或额外迁移框架；当前代码对 `version >= current` 已直接返回，本批只验证当前版本配置不会被后续提交改写为 v1。**未来版本仍可能被启动保存回写并丢失未知字段，本批不宣称解决；读取后原样保留或拒绝回写需另写策略。**

**验收场景：**

- 新配置的 `schemaVersion == CONFIG_SCHEMA_VERSION`，保存、恢复备份后仍为当前版本。
- v1 且仍指向应用私有目录的书库只重置一次 `androidStorageInitialized`；公共目录、SD 卡和用户手选目录不被重置。
- 无版本旧配置仍执行域名迁移和登录默认值处理；明文凭据仍能按既有逻辑加密保存。

**回退：** 回退两个文件的版本赋值和测试，无新增磁盘格式。回退后可能恢复重复迁移，但不删除漫画文件。

### B02 章节封包结果与任务终态一致

**目标：** 修复“封包中暂停使 `Completed` 迁移被拒绝，但任务仍从运行期映射移除”的边界，并明确取消与已提交 CBZ 的关系。

**文件：** 修改 `src-tauri/src/download_manager/download_task.rs`、`download_manager/mod.rs`、`download_queue.rs`、`state_transactions.rs` 及对应测试；共用恢复分类放在队列模块，归档补跑沿用管理器现有调度，不另建服务。

**实施：**

1. 新增一个由 `event_lock` 保护的封包成功收尾函数：读取当前状态；`Cancelled`、`Failed` 不被覆盖，其余非终态（包括恢复后的 `Pending`）写入 `Completed`，清理失败记录并设置 `Done`，统一更新队列和发布事件。
2. `set_stage` 的发布也走相同事件锁，避免阶段和状态形成两份不一致的发布序列。不修改下载中正常暂停和失败重试的任务 ID 语义。
3. `process` 在封包返回并写回终态后才移除运行期任务。若取消先于收尾登记，保持 `Cancelled` 且不触发该次合并；若收尾先登记完成，后续取消不改写完成状态。已物理提交的 CBZ 始终保留，由书库身份扫描认回。
4. 取消仍优先停止后续写入，不承诺回滚已成功提交的 CBZ。普通封包中暂停会暂停 future 轮询，恢复后继续；只有最终迁移与暂停的竞态按完成结果收尾。
5. 启动、备份导入和事务恢复共用 `Done` 恢复规则：不再下载，保留可见完成历史，并按仍存在的归档意图调度一次补跑。若旧文件缺失，由用户重新创建下载，不自动猜测。

**验收场景：**

- 普通封包中暂停后，future 不再推进；恢复后继续封包并完成。模拟最终迁移前的暂停竞态，任务为 `Completed + Done`，运行期映射移除，点继续不会出现“未找到任务”。
- 图片传输中暂停仍为 `Paused`，恢复后复用合法临时图片；`Cancelled` 不被完成或失败覆盖。
- 封包返回前取消不触发该章节的整本合并；封包返回后的操作不抹掉已生成 CBZ 的完成记录。
- 磁盘含 `Paused + Done`、`Pending + Done` 或 `Downloading + Done` 时不再恢复为下载任务；`Paused + Archiving` 仍需重新校验，不假定旧 CBZ 完整。
- 完成但尚未整合时进程退出，重启后仍会根据归档意图补跑，不因丢弃旧任务记录而跳过整合。
- 保存队列失败不会把“已持久化”当作事实报告，B08 提供用户可见承接。

**回退：** 回退本批四个文件的终态和恢复分类，队列格式未变。已生成 CBZ 不删除；旧逻辑可能重新出现暂停记录问题，但不影响其他文件。

### B03 创建、恢复与整本合并共用登记互斥

**目标：** 关闭 `is_running` 检查与任务登记之间的窗口，补齐恢复和手动整理入口。

**文件：** 修改 `src-tauri/src/archive_finalize.rs`、`download_manager/mod.rs`、`commands/download_commands.rs`。

**实施：**

1. 在 `ArchiveFinalizeState` 增加“检查并登记 running”的短临界区 API，与 `try_begin` 共用 `runs` 锁。调用方先取得任务映射写锁，再调用它确认无运行、无待补跑；登记成功后才执行实际 I/O。不要提供“持 runs 锁执行任意闭包”的 API，以免藏入磁盘写入和反向锁。
2. 创建、批量创建和恢复均先持任务映射写锁，再短暂检查归档状态并释放 `runs` 锁；队列写入和运行期任务登记仍在任务映射锁内完成，任务 `spawn` 放到全部协调锁外。B10 接管批量落盘前，B03 沿用各入口现有队列写入方式。
3. 归档开始持任务映射写锁重新检查活跃任务，并在保持该锁的同一登记边界写入 `running`、释放 `runs` 锁；实际 I/O 在全部锁外执行。`spawn_finalize_if_idle`、手动 `promote_comic_archive` 和补跑统一走此入口。
4. 保留 `running`、`rerun`、`FinalizeGuard` 和归档内第二次活跃检查。首批不增加章节提交计数，因为封包发生在任务从运行期映射移除之前。
5. 锁顺序统一为“任务映射 → 归档协调 → 任务事件 → 队列”，不在协调锁内等待归档线程。归档收尾读取任务映射的现有路径不得反转；实现后用调用链审查确认没有 ABBA。

**验收场景：**

- 用可控闭包分别让创建先登记、归档先登记；两种顺序下都不会出现归档运行中新增活跃任务。
- 归档运行中恢复同一漫画返回“正在整理 CBZ”类错误，原任务仍为 `Paused`；其他漫画不被阻塞。
- 手动整理与自动整理不能同时运行；运行期间产生的归档请求仍记录 `rerun` 并补跑。
- 章节封包尚未结束时，该任务仍能被活跃检查看见；归档不得提前清理其来源。

**回退：** 回退三个文件的协调入口，恢复原 `is_running` 检查；无持久化格式变化。书库删除的更广泛“检查—取消—删除”事务不在本批宣称解决。

### B04 阅读器与收藏重试保留失败请求

**目标：** 重试用户刚刚失败的目标，明确保护阅读进度。普通网络失败时当前 `progressSnapshot` 会因章节数据为空而不写；空图片分支和成功重试到第 1 页才是需要修复的路径。

**文件：** 修改 `src/dialogs/ReaderDialog.vue`、`src/panes/FavoritePane.vue`；扩展 `tests/readerNav.test.mjs` 或对应的局部状态测试。

**实施：**

1. `loadChapter(comicId, chapterId, page)` 在重置页面前保存完整 `lastLoadAttempt`；错误按钮通过无参数重试函数读取它，不使用默认第 1 页。
2. 仅在成功获得非空章节数据后保存进度；错误、空图片和过期响应只清理对应加载状态，不写第 1 页。保留滚动定位、预加载、翻页键和 `flushProgress`。
3. `FavoritePane` 保存带 `uid`、`sessionEpoch`、`folderId`、`page`、`sort` 的 `lastFavoriteAttempt`；重试仅在会话仍一致时使用它。
4. 收藏的三个 selected refs 继续表示最后成功查询，不在失败时提前变更。空页自动回退到上一页等递归请求也必须把 `lastFavoriteAttempt` 更新为实际发出的页码，不能只记录入口参数。保留 generation、uid、sessionEpoch 和 `favoriteRevision` 全部守卫，不删除收藏同步能力。

**验收场景：**

- 从第 37 页打开失败，原存储进度不变；重试仍请求第 37 页，成功后按实际总页数夹紧。
- 失败切换章节、关闭阅读器或发起新请求，旧响应不写进度；滚动和分页阅读均保持原有操作。
- 收藏夹 F 第 3 页按某排序失败后，重试仍是 F/3/该排序；成功后才更新选中态。
- 账号或会话代际变化后，旧收藏请求和重试不覆盖新会话；收藏操作修订号仍生效。

**回退：** 回退两个 Vue 文件和相应测试，无数据迁移。

### B05 队列内容问题不阻止启动

**目标：** 未知版本或多个原子写恢复备份不再使 setup 在主窗口创建前失败；损坏 JSON 已有备份后空队列启动的逻辑，本批只补齐保留副本和提示。

**文件：** 修改 `src-tauri/src/download_queue.rs`、`archive_intents.rs`、`download_manager/mod.rs`、`commands/download_commands.rs`、`commands/config_commands.rs`、`state_transactions.rs`、`diagnostics.rs`、`lib.rs`（仅在注册命令需要时）；生成绑定归入 B08 统一处理。

**实施：**

1. 引入 `QUEUE_FORMAT_VERSION`，让保存、备份导出、备份解析共用常量。首批仍只读写 v1。
2. 加载返回“队列 + 待展示提示”，内容级问题转为空队列启动。未知版本和多备份保留原文件或保留副本，不静默删除；复用现有损坏 JSON 测试，不重复实现一套解析恢复。
3. 重命名备份失败时改用独立运行队列路径，防止后续保存覆盖未能移走的原文件；提示中给出保留位置。
4. 管理器保存一次性启动提示，前端在初始任务水合后获取并显示；不能只发一个窗口尚未创建时的后端事件。
5. 归档意图的未知版本、多备份和改名失败也纳入同一启动安全检查；未知版本不得静默忽略。该文件损坏后的保留策略与队列一致。
6. 若启用备用运行路径，必须让备份、事务恢复、诊断和重启使用同一活动路径，不能只改 `save` 的自持路径。保留副本默认需手动恢复，不承诺旧版本会自动读取改名后的文件。
7. 备份导入与事务恢复仍拒绝未知版本并返回命令错误，但不影响当前运行队列。诊断记录提示摘要，不包含凭据。
8. 本批只处理这两个状态文件，不宣称配置读取、日志初始化、主窗口创建等其他 setup 错误也已容错。

**验收场景：**

- v1 正常恢复；未知 v2、损坏 JSON、多备份均能继续创建主窗口，任务列表为空且出现一次明确提示；归档意图未知版本同样有提示。
- 损坏 JSON 可改名与不可改名、只读目录、多个 `.backup-*`、备份事务中的未知版本分别覆盖；未运行前不宣称已通过。
- 原文件或保留副本仍在；备份改名失败也不会随后被新队列覆盖。
- 备份导入未知版本返回该次操作错误，不阻断应用；B02 的 `Done` 过滤与本批兼容。

**回退：** 恢复原加载路径和提示命令；没有改变现有 v1 文件结构。回退后未知版本会恢复为启动错误，因此应优先保留本批。

### B06 合并包按包内身份识别

**目标：** 长标题截断或云端改名后，详情刷新仍能识别同一个整本 CBZ。

**文件：** 修改 `src-tauri/src/comic_scanner.rs`、`archive_finalize.rs`，必要时小幅收敛 `utils.rs` 的命名辅助函数。

**实施：**

1. 去掉 `update_chapter_infos_fields` 对未截断漫画名前缀的强制预筛，在原有候选目录内读取 `.cbz` 的整本包身份，不扩大为无界递归扫描。
2. 应用生成的整本包以包内 `comic_id` 和章节 ID 集合为准；含 `chapter.json` 的章节包必须匹配漫画与章节身份。仅对没有这些元数据的外来旧包保留现有兼容回退。
3. 文件名生成继续共用截断与 `[JM{id}]` 回退规则。`resolve_merged_target` 与 `archive_belongs_to_comic` 改为复用完整 `read_merged_archive_identity`：只有漫画 ID 相同且确实具有整本布局，才允许作为本漫画的已有合并目标；只匹配漫画 ID 的单章包或无元数据同名文件仍回退到带 ID 的目标，两个候选均被占用则拒绝，不覆盖。
4. 首批不直接加入未经测量的大缓存。先在 release 构建测量去掉预筛后的详情刷新成本；若超出实际可接受范围，本批的发布门槛是增加有界的“路径 + 长度 + 修改时间”身份缓存，并验证归档提交、导入和删除均使其失效。

**验收场景：**

- 超过文件名截断长度的漫画和云端改名后的旧合并包，包内章节仍标记已下载。
- 同名不同漫画、普通单章包和无元数据外来包不串用身份。
- 合并目标遇同名章节包时使用安全回退，不覆盖来源文件；现有根目录和身份校验不放宽。

**回退：** 回退扫描与命名辅助函数，不移动或删除任何现有文件。

## 4. 阶段二：界面反馈

### B07 书库刷新单入口与失效代际

**目标：** 隐藏页和传输子页不扫描；扫描期间的新变化不被旧结果清掉；首次进入不重复扫描。

**文件：** 修改 `src/store.ts`、`src/panes/DownloadedPane/DownloadedPane.vue`、`src/AppContent.vue`、`src/panes/SettingsPane.vue` 中改变书库目录后的刷新调用。

**实施：**

1. store 增加 `downloadedLibraryEpoch` 和 `invalidateDownloadedLibrary()`。下载完成、归档结束、导入、删除、目录变化只标 stale 并递增代际，不直接扫描。
2. `refreshDownloadedComics` 开始时记录 generation 和 epoch；返回后两者都未变才提交列表和清 stale。代际变化则丢弃结果、保持 stale，并由可见页调度器补跑一次。
3. 页面设置唯一 `requestLibraryRefresh({ source, force })`：仅激活且顶层/子页均为书库时自动执行，连续事件短去抖，在途请求最多登记一次补跑；手动操作可立即刷新。
4. 所有 `onMounted`、`onActivated`、tab/subtab/stale/downloadDir 监听进入同一入口。`stale: true → true` 不会再次触发 watch，因此必须显式处理在途期间的 pending，而非只依赖 watch。
5. 任务水合时的历史 `Completed` 不触发书库失效；只有本次会话新到达的完成事件才标记，避免启动时重复扫描。
6. 诊断继续复用后端最近一次扫描缓存。只有列表扫描成功且代际仍有效时才更新诊断，不声称 `diagnoseLibrary` 当前会额外做一次全量扫描。
7. 手动失败给一次错误提示并保留旧列表；自动失败记录日志、保持 stale。下载目录改变时清空旧列表并取消旧结果提交资格。

**验收场景：**

- 首次进入只调用一次 `getDownloadedComics`；传输子页、其他 tab 和水合历史完成事件均为零自动扫描。
- 连续多个下载/归档事件合并；扫描中发生新变化时旧结果不提交，结束后可见页补扫一次。
- 删除、导入和目录变更不错误显示旧目录内容；诊断与列表来自同一次有效扫描。
- 手动失败可见，自动失败不连续弹提示；离开书库页后的在途结果不能清掉新的失效标记。

**回退：** 回退 store 代际和页面调度入口，无磁盘数据变化。

### B08 后台失败承接后再移除通用日志通知

**目标：** 命令错误只由调用方展示一次；后台存储失败不只藏在日志里。

**文件：** 修改 `src-tauri/src/events.rs`、`download_queue.rs`、`archive_intents.rs`、`commands/system_commands.rs`、`lib.rs` 注册处、`src/store.ts`、`src/AppContent.vue`、`src/panes/SettingsPane.vue`；通过既有生成命令更新 `src/bindings.ts`。

**实施：**

1. 新增窄的 `BackgroundFailureEvent { domain, title, message, dedupeKey }`，只覆盖无命令返回承接的队列保存和归档意图保存失败。沿用现有事件注册与绑定生成，不引入新框架；更新 `lib.rs` 的 `collect_events!` 与相应事件数量测试，按现有 `pnpm gen:bindings` 离线流程生成绑定。
2. 队列保存失败保留 dirty，归档意图采用明确的 dirty 重试或失败回滚，不能仅弹提示却让内存与磁盘永久分叉。任一重试不得覆盖更新后的意图。
3. `initLogListener` 只保留有上限的日志收集，删除 ERROR→notification 分支。取消操作和正常业务拒绝不属于后台故障。
4. `clear_logs` 有真实删除失败时返回 `CommandError`，无失败才显示成功；不扩大可删除文件范围。
5. 设置项改称“文件日志等级”，与实际只过滤文件层的行为一致；Off 不等于关闭前端事件采集。
6. 检查归档失败仍由 `ComicArchiveEvent`/`archiveFailures` 展示；后台刷新失败由 B07 在可见页处理。JS 异常采集不塞进本批，避免和错误通道改造耦合。

**验收场景：**

- 模拟队列或归档意图写盘失败：日志有完整错误，界面出现一次有限时长提示；恢复后再次失败可重新提示。
- 普通命令失败只有调用方提示，不再叠加 `duration: 0` 的“系统错误”；正常暂停、取消不弹后台错误。
- 日志清理部分失败不显示成功，非受管文件仍保留；日志等级文案与实际范围一致。

**回退：** 移除领域事件和监听器，恢复原日志通知桥；不改变用户数据或生成绑定以外的协议。

### B09 命令式确认框接入现有返回机制

**目标：** Android 返回和 Escape 先处理最上层确认框，所有退出路径都完成原有回调或 Promise。首批覆盖五个等待布尔结果的确认操作；不等待 Promise 的导入 warning 在 B12 单独复用包装。

**文件：** 新增 `src/composables/useDialogBack.ts`；修改 `src/composables/useAndroidBack.ts`（或复用其注册 API）、`DownloadedPane.vue`、`SettingsPane.vue`、`ProgressesPane/components/UncompletedProgresses.vue`。

**实施：**

1. 包装五处确认：删除漫画、恢复设置、重置设置、更改目录、取消全部；不替换已有 `useBackHandler` 的组件式弹窗。部分导入 warning 没有 Promise 挂起风险，不与这五处混为同一缺陷。
2. 弹窗打开时注册高于底层页面的返回处理，关闭时注销。返回触发与取消相同的真实回调，并让 Promise 恰好结算一次。
3. Naive UI 的 Escape/遮罩路径不一定触发 `onClose`，不能只依赖 `destroy()` 或 `onClose`；正按钮、负按钮、遮罩、Escape、程序化关闭均显式走幂等 settle。
4. 异步确认执行中返回键只消费、不关闭，避免界面看似取消而后台仍执行。页面失活或卸载时注销并按取消语义结算，不能遗留隐藏页面的处理器。
5. 不改变阅读器翻页键和底部进度条；重复 Escape 监听的清理单独静态核对，不借本批重写阅读器。

**验收场景：**

- 五处确认中返回/Escape 只关闭最上层，底层页面不切换；连续打开关闭不累积处理器。
- “取消全部”经取消、遮罩、返回、关闭均使 await 结束，且不会调用取消命令。
- 异步删除或恢复执行中返回不伪报取消；正向操作和失败保留弹窗的行为不变。

**回退：** 移除包装并恢复原五处确认调用，无数据变更。

## 5. 阶段三：减少重复工作

### B10 队列批量写入与发布顺序

**目标：** 批量入队、恢复、计费暂停各只有一个显式批量保存，不承诺并发 worker 绝不追加保存。

**文件：** 修改 `src-tauri/src/download_queue.rs`、`download_manager/mod.rs`、`download_manager/download_task.rs`、`commands/download_commands.rs`。

**实施：**

1. 新增 `insert_many`，将已有 `update_many` 生产化。候选状态在队列锁内构造，保存失败恢复整批内存，不 spawn、不留下半批；不得覆盖先前已有任务。
2. 恢复先构造任务及计费网络下的初始状态，再批量保存和登记，锁外启动。单个坏条目按明确失败处理，不拖垮其他合法任务。
3. 计费暂停先在事件锁内收集实际变化快照，锁外一次批量保存，再按队列分配的新 revision 发事件。保留“仅 Wi-Fi”策略的现有检查顺序。
4. 后端现有迟到写回保护只有 `task_id`；worker 快照的 `revision` 固定为 0，前端 revision 是队列分配的事件排序值。本批先用 B02 的统一事件锁消除阶段/状态发布交错，保留 task_id 校验和单调 revision。完整 revision 前置校验涉及 insert、恢复、替换和命令写回，需另有失败样例后单独设计，不与批量保存捆绑。
5. 保存失败保留 dirty 和 B08 的错误承接；界面可以反映内存中的已暂停或已完成状态，但必须同时说明恢复状态未保存。下一次有效保存重试，不静默吞错；终态先写内存即可移除运行期对象，不要求为磁盘故障永久保留 worker。

**验收场景：**

- N 章创建/恢复/计费暂停的批量入口各只调用一次显式 save；记录并发 worker 产生的额外保存，不写成绝对一次。
- 保存失败时无新任务启动、无半批内存；旧任务不丢失，错误经 B08 可见。
- 同一 chapter_id 的旧 task_id 被拒绝，新 task_id 不受旧 worker 影响；事件 revision 保持单调，锁外发布。
- 正常下载、暂停、恢复、重试、取消与重启后状态一致。

**回退：** 回退批量 API 和调用点，队列 JSON 仍保持 v1，不需要迁移或删除文件。

### B11 统一批量下载分类和失败语义

**目标：** 已下载中或已暂停不是“创建失败”；真实失败不中断其他可创建章节，也不掩盖部分已启动的事实。

**文件：** 修改 `src-tauri/src/commands/download_commands.rs`、`download_manager/mod.rs`；扩展纯分类与批量结果测试。

**实施：**

1. 共用“未完成章节收集”和现有任务分类：`Pending`、`Downloading`、`Paused` 归为跳过，真实创建/存储错误归为失败。

3. 返回创建、跳过、失败计数及有限错误示例。部分成功同时有失败时，文案明确已启动部分，不能让用户误以为全部未执行。

**验收场景：**

- 批量落盘失败：无任务启动，返回一个明确存储错误；部分创建失败时报告准确计数。
- 收藏批量下载复用同一分类；单章重复创建仍有明确反馈，网络许可检查顺序不变。

**回退：** 回退命令和 manager 的批量分类，不改变队列或收藏数据。
